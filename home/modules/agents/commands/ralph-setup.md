# Ralph Loop Setup Wizard

ユーザーと対話しながら、最適な ralph-loop の呼び出しを組み立てる。

## 入力の確認

$ARGUMENTS が指定されている場合、それをタスクの初期情報として扱う。

## ヒアリング手順

以下のステップを対話的に進める。一度に全部聞かず、ステップごとにユーザーと会話すること。

### Step 1: タスクの把握

ユーザーにタスクの目的をヒアリングする。以下を明確にする:

- 何を達成したいのか
- 対象のファイル・ディレクトリ
- 技術的な制約や前提条件

必要に応じてコードベースを読んで文脈を理解する。

### Step 2: 完了条件の定義

`--completion-promise` に設定する文言を一緒に決める。

良い完了条件の基準:
- **客観的に検証可能** であること（例: "All tests passing", "No TypeScript errors", "Build succeeds"）
- **曖昧でない** こと（"コードが改善された" はダメ）
- **Claude が自力で判定できる** こと（コマンド実行で確認できるのが理想）

ユーザーの意図に基づいて具体的な文言を提案し、合意を取る。

### Step 3: 反復回数の決定

`--max-iterations` を決める。目安を提示する:

- 小規模（バグ修正、小さなリファクタ）: 5-10
- 中規模（機能追加、テスト整備）: 10-20
- 大規模（大きなリファクタ、複数ファイルの変更）: 20-50

無制限（0）は推奨しない。理由も説明する。

### Step 4: プロンプトの構成

ここまでの情報をもとに、ralph-loop に渡すプロンプトを組み立てる。

良いプロンプトの構成:
1. タスクの明確な説明（何を、なぜ）
2. 対象の範囲（どのファイル・ディレクトリ）
3. 各イテレーションで行うべきアクション
4. 成功の判定方法（どのコマンドで確認するか）

### Step 5: 確認と実行

組み立てた ralph-loop コマンド全体をユーザーに提示する:

```
/ralph-loop [プロンプト] --completion-promise '[条件]' --max-iterations [N]
```

ユーザーの確認を得てから、Skill tool で `ralph-loop` を実行する。

## 重要な注意事項

- completion-promise は Claude が嘘をつけない仕組み。真に検証可能な条件のみ設定すること
- プロンプトが具体的であるほどループは早く収束する
- 曖昧な指示は無駄なイテレーションの原因になる
